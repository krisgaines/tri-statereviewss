# Tri-State Reviews — Project Guide

## Purpose and architecture

This is a responsive marketing site for Tri-State Reviews, a local social media management business serving Ohio, Pennsylvania, and West Virginia. TanStack Start renders the React frontend on Netlify. Contact and support submissions use a custom Netlify Function and Netlify Database, not Netlify Forms. Resend provides transactional mail after a site operator configures a verified sender and API credentials.

## Key files

- `src/routes/index.tsx`: landing-page sections, pricing and sample-project data, navigation, form components, accessible native dialogs, and interaction state.
- `src/routes/__root.tsx`: HTML shell, stylesheet, favicon, finished title, description, and social metadata. Do not add `og:image`; the platform supplies it.
- `src/styles.css`: cream/olive design tokens, typography, layout, responsive breakpoints, interaction states, and reduced-motion overrides.
- `src/router.tsx`: TanStack Router setup. The route tree is generated by the framework; do not hand-edit generated route files.
- `public/img/`: local stock photographs used in sample creative work. Serve them through Netlify Image CDN rather than full-size originals.
- `db/schema.ts`: the sole source of truth for the structured inquiry schema.
- `db/index.ts`: invocation-time creation of the native Netlify Database Drizzle client.
- `drizzle.config.ts`: PostgreSQL migration generation, targeting `netlify/database/migrations/`.
- `netlify/functions/contact.mts`: `POST /api/contact`, request validation, rate limiting, durable save, safe retry handling, and immediate email processing.
- `netlify/functions/checkout.mts`: `POST /api/checkout`, server-validated pricing, Stripe-hosted one-time checkout, and monthly subscriptions.
- `netlify/functions/stripe-webhook.mts`: signed Stripe webhook verification at `POST /api/stripe/webhook`; acknowledges events without persisting a second payment ledger.
- `netlify/lib/email.ts`: Resend mail content, independent owner/customer delivery tracking, database leasing, and retry timing.
- `netlify/functions/email-retry.mts`: production-only scheduled worker, running every five minutes with a small concurrent batch.
- `README.md`: local development, operator setup, content editing, persistence, and email activation instructions.
- `.netlify/results.md`: implementation handoff summary consumed by the platform.

## Conventions

Use strict TypeScript, descriptive names, React hooks for temporary UI state, and semantic HTML. Keep the muted cream, olive, and yellow palette coherent. Use Lucide icons or code-native SVG assets; avoid emoji iconography. Preserve accessible labels, focus styles, keyboard navigation, form states, and reduced-motion behavior. Frontend modules may use the `@/` alias; server-side relative imports use `.js` extensions for ES module resolution.

Functions use the modern default-export Web Request/Response format and `.mts` filenames. Runtime environment access uses `Netlify.env.get`, not `process.env`. Create the database connection during an invocation, not during module evaluation. Never send database code or email-service credentials to the browser. Never log credentials or inquiry content. No inline code comments are needed unless specifically requested.

## Data and delivery invariants

Use Netlify Database for structured persistent data, with `@netlify/database` and the native `drizzle-orm/netlify-db` adapter. Drizzle packages are installed from their `beta` dist-tags because the platform skill requires that adapter line. Do not substitute local files, memory, Blobs, or an external database for inquiry storage.

Keep all schema changes in `db/schema.ts`, check migration state with `netlify db status`, and generate migrations using `pnpm exec drizzle-kit generate --name descriptive_change`. Do not manually apply migrations. Netlify handles them on deployment. Do not edit an applied migration. The current initial migration was generated before any database branch existed.

Save a submission before attempting email. Preserve client-generated UUID idempotency, payload matching, consent validation, origin checks, input bounds, and honeypot/rate-limit protections. There must be no public inquiry-list endpoint. Persist independent notification and confirmation timestamps, acquire a lease before processing mail, and keep provider idempotency keys stable. Transactional confirmations must not include arbitrary user-submitted messages. A successful provider response means acceptance, not guaranteed inbox delivery.

Both owner notification types go to `tristatereviewss@gmail.com`. Read only `RESEND_API_KEY` and `RESEND_FROM_EMAIL` for sending configuration. The sender must be a verified address, not the Gmail recipient. Missing configuration must not prevent saving a valid message or produce a false claim of email delivery. Failed mail retries with bounded exponential backoff, up to twelve attempts; exhausted records require operator attention. Scheduled retries do not run on deploy previews.

Stripe checkout uses server-only runtime variables: `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET`. Validate all plan names, prices, and billing cadence on the server; never accept a customer-supplied amount, expose Stripe credentials to the browser, log provider payloads, or trust arbitrary redirect URLs. Stripe hosts checkout and stores its payment/subscription records; do not create a second payment ledger unless a future requirement calls for it. Verify webhook signatures against the raw request body and acknowledge only signed events.

## Content invariants

Preserve USD pricing: Associates $150, Friends $300, and Family $450 per month; customers may pay once for a single month or subscribe to automatic monthly renewal. Blueprint is $200 and one-time only. Inquiries do not charge or subscribe customers. Exact content deliverables are agreed with clients before service.

The portfolio contains fictional concepts approved by the user as samples. Keep all sample labels and disclaimers unless replacing them with authorized, factual client work. Never fabricate clients, testimonials, or performance metrics. Do not add social-account links until actual profiles are provided.

## Local development and validation

Use Node.js 22 and pnpm. `pnpm install` installs dependencies. `netlify dev --port 8889` starts the app and Functions together on a linked site. Functions require Netlify's database runtime configuration. Real email requires the operator setup documented in README.

In the managed agent build environment, do not run local builds, development servers, typechecks, or test commands; the pipeline validates deployment automatically. Database migration generation is allowed. Do not create git commits or inspect the `.git` directory. Record meaningful completed changes and any remaining operational setup in `.netlify/results.md`.
